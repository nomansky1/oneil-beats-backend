# Raceland

Low-poly post-apocalyptic wasteland arcade physics racer for Android. Unity, URP,
touch controls, sideloadable APK.

Standalone project. No shared code, assets, or repo history with Void Drift or
Global Drift.

---

## ⚠️ Read this first — build status

**The C# in this repo has never been compiled.** It was written in a headless Linux
container with no Unity, no Blender, and no .NET toolchain installed, so there was
nothing to compile it against. It is written against the Unity 2022.3 LTS API and has
been read through carefully, but "carefully reviewed" is not "it builds."

Expect to fix a small number of compile errors on first open. Nothing here should be
taken as verified until you have seen it run.

What that means practically:

| Thing | Status |
|---|---|
| Gameplay C# (physics, camera, damage, race loop, UI) | Written, **not compiled** |
| Grey-box track + buggy + UI scene | Generated by an editor script, **never executed** |
| Handling feel (spring rates, grip, power) | Numbers reasoned from mass and gravity, **never driven** |
| Android build settings | Applied via script, **never built** |
| APK | **Does not exist** |
| Rodin / Blender assets | **None generated** — see [Docs/ASSET_PIPELINE.md](Docs/ASSET_PIPELINE.md) |

The physics tuning in particular is a starting point, not an answer. Arcade feel is
found by driving, and nobody has driven this yet.

## Getting it running

1. **Unity 2022.3 LTS** (`ProjectVersion.txt` pins 2022.3.62f1 — any 2022.3.x is fine).
   Install with the **Android Build Support** module, including **OpenJDK** and
   **Android SDK & NDK Tools**.
2. Open the project. First import takes a while — URP is pulled from the package
   registry.
3. Unity will prompt to import **TMP Essential Resources**. Accept it. Without it every
   UI label renders blank.
4. Set up the render pipeline:
   - `Assets > Create > Rendering > URP Asset (with Universal Renderer)`
   - Assign it in `Project Settings > Graphics > Scriptable Render Pipeline Settings`
   - **And** in `Project Settings > Quality`, for every quality level
   - Verify with `Raceland > Setup > Validate Render Pipeline`
5. Run `Raceland > Setup > Apply Everything`.
6. Run `Raceland > Build Playable Grey-Box Track`.
7. Open `Assets/_Project/Scenes/Raceland_Track01.unity` and press Play.

## Why there is a grey-box track

The brief sequences art generation (Rodin → Blender) ahead of the Unity work. That
ordering carries a risk: the physics is the part that either feels good or doesn't, and
no amount of art rescues a buggy that drives badly. Finding that out after the art
pipeline is finished is the expensive way to find out.

So `Raceland > Build Playable Grey-Box Track` generates a complete, drivable circuit out
of Unity primitives — road, barriers, checkpoints, boost pads, a jump kicker,
destructible wrecks, billboards, a buggy with working suspension and tear-off panels, the
chase camera, and the full UI.

Everything it makes is ordinary scene objects. Swapping a grey box for a real Rodin mesh
is an art task, not a code change. Tune the handling on boxes while the art pipeline
runs in parallel, then drop the meshes onto physics that's already proven.

## Project layout

```
Assets/_Project/
  Scripts/
    Core/        input hub, saved settings, frame-rate bootstrap
    Vehicle/     suspension, buggy controller, boost, damage, audio, respawn
    Camera/      chase camera (follow, FOV, shake)
    Track/       checkpoints, finish line, race manager, boost pads, destructibles
    Gameplay/    stunt scorer
    UI/          touch controls, HUD, menus
  Editor/        project setup, layer setup, scene builder, UI builder, Rodin importer
  Art/           Blender-processed, Unity-ready meshes
    Rodin/       raw Rodin exports — auto-configured on import, see below
  Scenes/ Prefabs/ Materials/ Audio/ UI/
```

Anything placed under a folder named `Rodin/` gets import settings applied
automatically: scale locked to 1 unit = 1 metre, hierarchy preserved (so Bang Parts
splits survive), textures capped at 1024 and ASTC-compressed for Android, and a warning
if a mesh is over the triangle budget. See `Editor/RodinAssetPostprocessor.cs`.

## How the physics works

Raycast suspension, not `WheelCollider`. WheelColliders bring a friction model tuned for
realism that fights the springy, exaggerated feel the brief asks for, and they are
notoriously fiddly. A spring + damper cast per corner gives a handful of numbers that map
directly onto how the car feels.

Per grounded wheel, each `FixedUpdate`:

1. **Suspension** — spring force from compression, damped by compression velocity. The
   spring may push but never pull.
2. **Grip** — the lateral velocity at the contact patch, cancelled by a force scaled by
   the grip curve. Grip falls off with speed so the back can step out, and scales with
   how loaded the wheel is so an unweighted inside wheel doesn't hold the car up.
3. **Drive** — power curve against normalised speed, so top speed emerges naturally
   instead of being clamped.

Plus, on the body: an anti-roll bar across each axle, speed-squared downforce, and direct
rotation control while airborne — that last one is what makes flips deliberate rather
than random.

The starting numbers: 1200 kg, gravity −18 m/s² (heavier than real, so jumps land
snappily instead of floating), 42 kN/m springs giving ~23% static compression, ~17 m/s²
of acceleration. Centre of mass pulled 0.55 m below the body origin — that single value
is what stops the buggy rolling in every corner, and it's the first thing to reach for if
handling feels wrong.

**Everything in that paragraph is arithmetic, not observation.** Tune by driving.

### The one collision rule that matters

Debris must not collide with the vehicle. Without it, a torn-off panel bounces back into
the buggy, triggers another impact, tears off another panel, and the car disassembles
itself in about a second. `Raceland > Setup > Create Layers, Tags and Collision Matrix`
sets this — **verify it stuck** in `Project Settings > Physics > Layer Collision Matrix`,
because setting the matrix from script does not reliably persist. Set the checkboxes by
hand once if needed.

## Game modes

Both are built, time trial is the default (brief §14.4, confirmed).

- **Time trial** — start line → 4 checkpoints → finish, timed, best lap saved per track.
  Checkpoints must all be taken or the finish crossing doesn't count, so the course can't
  be cut. Respawn at the last checkpoint on flip, fall, or getting stuck.
- **Stunt score** — same track, no finish line, 120-second round. Points for air time,
  flips, barrel rolls, near misses and wrecked obstacles, with a combo multiplier that
  builds on clean landings and resets on a crash. Tricks only bank when you land
  upright — crash out mid-flip and the pending points are lost.

Switch modes from the main menu. The stunt scorer runs in both modes, so time trial shows
a bonus stunt score on the results screen.
